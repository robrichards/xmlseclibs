XX, Nov 2026, 4.1.0
Bug Fixes:
- addReference() and addReferenceList() digest a reference without
  comments, matching verification. xmlseclibs resolves an omitted URI as
  the whole document (XMLDSig leaves an omitted-URI target to application
  context). URI="" and URI="#id" follow their own specified
  comment-removal rules. Those three forms are digested without comments,
  so a WithComments canonicalization transform sees no comments on either
  side. Previously a reference with a WithComments transform over XML
  that contained comments produced a digest that validateReference() and
  verifyDocument() could not reproduce. XML without comments, and every
  transform that is not WithComments, produce the same digest as before.
  Signatures with WithComments over XML containing comments produced by
  earlier versions did not verify and must be re-signed.
- addReference() and addReferenceList() no longer leave a partly built
  Reference in SignedInfo when an exception is thrown while the Reference
  is being built.   An ID attribute added for that Reference is removed, and
  an ID attribute that was overwritten is restored with its original text.
  A namespace prefix binding added for that ID is removed with it,
  including a redeclaration of a prefix that was bound to another
  namespace. A binding that was already on the element or an ancestor
  is left in place.
- Decrypted Element and Content data is now parsed in the namespace context
  of the EncryptedData's parent, so prefixes and default namespaces inherited
  from ancestors resolve as they did before encryption. Existing ciphertext
  recovers bindings that are still present on its original parent; data
  produced by an older serializer that omitted an explicit xmlns="" cannot
  indicate that the element had no namespace and takes the parent's default
  namespace.
- Encrypted Element data now carries its in-scope namespace declarations,
  and xmlns="" is written where needed, so decryptors that do not parse in
  context restore the same namespaces.
- Encrypting a whole DOMDocument now writes xmlns="" on descendants that
  have no namespace and sit under a default namespace (for example, nodes
  created with createElement), so they come back with no namespace after
  decryption. The caller's document is left unchanged.
- Signatures over encrypted-then-decrypted content (inclusive and exclusive
  c14n, enveloped and external references, Element and Content modes)
  previously failed to verify in several cases and now verify.
- A failed verifyDocument(), validateReference(), or verify() leaves
  getValidatedNodes() with no nodes, including when the failure is not
  an Exception. Nodes recorded for an earlier reference are cleared when
  a later reference in the same call fails.
  A later call on the same object does not keep nodes from an earlier
  success. verify() leaves those nodes in place when it returns 1.
- verifyDocument() checks the SignatureValue with the supplied key after
  SignedInfo is canonicalized and before any reference is looked up,
  canonicalized, or digested. An invalid signature fails before reference
  processing. Reference transforms are checked after the signature and
  before reference digests.
- verifyDocument() accepts only canonicalization transforms (c14n, c14n
  with comments, exclusive c14n, and exclusive c14n with comments) and the
  enveloped-signature transform. Any other transform, including XPath, is
  rejected before it is applied. This includes legacy mode.
- On validateReference(), verify(), and getValidatedNodes(), the returned
  node is the reference target. It may hold content outside the transformed
  data that was digested. Callers using XPath filtering must apply their own
  understanding of the transforms.
- Only one XPath transform per reference is supported, when signing and
  when verifying. Signing throws before it changes the document.
  $maxXPathTransforms remains and is effectively capped at 1; a lower value
  is still honored.
- XMLSecurityDSig::verify() throws when the key is not a signature key,
  including when allowedSignatureAlgorithms is null and the key comes from
  locateKey(). XMLSecurityKey::verifySignature() returns 0 for those key types.
- staticLocateKeyInfo() resolves a RetrievalMethod of type EncryptedKey with
  a same-document URI (#id) only when exactly one XML Encryption EncryptedKey
  element carries that Id. When more than one does, it throws "Multiple
  EncryptedKey elements with @Id='<id>'." before any candidate is processed,
  so the result no longer depends on document order. Elements in other
  namespaces, and other element types that use the same Id value, are not
  counted. A reference that matches no EncryptedKey, and the unsupported
  forms (empty or external URI, other Type), behave as before, as does an
  EncryptedKey embedded directly in KeyInfo. Documents that repeat an
  EncryptedKey Id and relied on the first element being used now throw.
- staticLocateKeyInfo() treats an EncryptedKey as key material only when its
  namespace is the XML Encryption namespace. fromEncryptedKeyElement() always
  requires a key-transport algorithm.
- Protocol element lookups keep the prefixes the library registered when the
  document also binds those prefixes. Evaluation of a caller-supplied XPath
  transform is unchanged.
- Caller-supplied idNS mappings take precedence over document prefix
  declarations when resolving references.
- XMLSecEnc::encryptNode() encrypts before it writes EncryptionMethod,
  replaces an existing direct EncryptionMethod child, and replaces
  CipherValue text. A later call on the same instance, including
  encryptReferences(), does not accumulate extra children.
- RSA-OAEP xenc:KeySize accepts xs:integer forms (optional leading plus,
  leading zeros, and surrounding whitespace). When present, it must match
  the RSA modulus size in bits. A mismatch uses the generic decryption
  failure. Omission is unchanged. Other unknown EncryptionMethod children
  are still rejected.
- enableLegacyMode() no longer lists the unsupported dsa-sha1 signature
  algorithm. XMLSecurityKey::DSA_SHA1 remains defined.
- XMLSecurityKey::loadKey() validates a symmetric key before storing it.
  PEM, certificate, DER, and too-short input is rejected without replacing
  a key already loaded on the object.
- Reject a symmetric key shorter than the algorithm requires when the key
  is used (AES-128: 16 bytes, AES-192: 24, AES-256: 32, TripleDES: 24,
  for CBC and GCM). Encryption names the short key; decryption uses the
  generic failure message. Longer keys are still truncated to that length.
- A successful loadKey() that is not a certificate clears any previously
  stored certificate thumbprint along with the certificate. A rejected
  load leaves both unchanged.
- XMLSecEnc::encryptKey() rejects a wrapping key that is not a key
  transport algorithm before it changes the document.
- Restore default algorithm fallback in verifyDocument(). When
  allowedSignatureAlgorithms or allowedDigestAlgorithms is null,
  verifyDocument() uses DEFAULT_SIGNATURE_ALGORITHMS or
  DEFAULT_DIGEST_ALGORITHMS for that call. An explicit list, including an
  empty array, is used unchanged. The caller's property values are restored
  afterwards. verify() and validateReference() still treat null as no
  restriction. Callers that need an extra algorithm (for example SHA-1
  digests) should add it to the list explicitly.
- Parse RSA-OAEP parameters (ds:DigestMethod, xenc11:MGF, xenc:OAEPparams)
  from the EncryptionMethod of an EncryptedKey/EncryptedData, applying the
  XML Encryption defaults (SHA-1/MGF1-SHA1, empty label) when absent. Restores
  interoperability with senders such as Shibboleth IdP. Encryption now
  serializes the OAEP parameters actually used. Adds
  XMLSecurityKey::setOAEPParameters()/getOAEPParameters(). (#293) by @cmcfadden.
- Apply allowedKeyAlgorithms to EncryptedKeys resolved via KeyInfo (embedded
  or RetrievalMethod). staticLocateKeyInfo() and
  XMLSecurityKey::fromEncryptedKeyElement() accept allowedKeyAlgorithms and
  allowedDataAlgorithms as optional arguments. allowedDataAlgorithms is
  copied onto the inner context and does not affect decryption.

BREAKING CHANGES:
- An EncryptedKey requires a key transport algorithm (RSA-1.5, RSA-OAEP,
  RSA-OAEP-MGF1P), independent of allowedKeyAlgorithms. Other algorithms
  are rejected when the key is resolved, in decryptKey(), in decryptNode()
  on an EncryptedKey, and in encryptKey() before the document is changed.
  Symmetric key types (AES, 3DES) no longer load certificates or PEM/DER
  key material in loadKey(); raw keys are unaffected. A symmetric key
  shorter than the algorithm requires is rejected (AES-128: 16 bytes,
  AES-192: 24, AES-256: 32, TripleDES: 24, for CBC and GCM). Longer keys
  are still truncated to that length.
- Reject encryption-only key types for signatures before emitting SignatureMethod.
  Signing throws an actionable exception. verify() throws for a non-signature
  key type. verifySignature() returns 0 for those key types. Use an
  RSA-SHA*, ECDSA-SHA*, or HMAC signature key type; encryption/key transport is
  unchanged.
- RSA_OAEP (xmlenc11#rsa-oaep) ciphertext produced by 4.0.0-4.0.2 used
  SHA-256/MGF1-SHA256 without declaring them, so it no longer decrypts through
  default key resolution (which applies the declared SHA-1 defaults). Regenerate
  it, or configure the key explicitly with setOAEPParameters(). There is no
  automatic fallback. Hand-built RSA_OAEP keys still default to SHA-256.
- XMLSecEnc::locateKey() reads only the direct EncryptionMethod child of the
  given node; passing an ancestor of EncryptedData/EncryptedKey now returns
  null, and EncryptedData without its own EncryptionMethod no longer picks up
  a nested EncryptedKey's algorithm.
- XMLSecEnc::locateKey() throws when a node has more than one EncryptionMethod.
- allowedKeyAlgorithms/allowedDataAlgorithms set on XMLSecEnc now also apply to
  EncryptedKey elements resolved by locateKeyInfo(); documents whose
  EncryptedKey uses an algorithm outside the configured list are rejected.
- XMLSecEnc::staticLocateKeyInfo() and XMLSecurityKey::fromEncryptedKeyElement()
  have two new optional parameters ($allowedKeyAlgorithms,
  $allowedDataAlgorithms). Subclasses that override either method with the
  4.0 signature fail with a PHP fatal error ("Declaration ... must be
  compatible"); add the two parameters to the override. New public methods
  XMLSecurityKey::setOAEPParameters(), getOAEPParameters(), setOAEPKeySize() and
  assertSignatureKey() can likewise conflict with same-named subclass methods.
- XMLSecEnc::$allowedKeyAlgorithms now defaults to
  XMLSecEnc::DEFAULT_KEY_ALGORITHMS (RSA-OAEP and RSA-OAEP-MGF1P) instead of
  null, a stricter default for key transport. The optional $allowedKeyAlgorithms
  argument of staticLocateKeyInfo() and XMLSecurityKey::fromEncryptedKeyElement()
  has the same default. RSA-OAEP with SHA-1 parameters (e.g. Shibboleth IdP)
  is unaffected. Decrypting RSA-1.5 key transport now requires both
  allowRSA15KeyTransport = true and RSA-1.5 in the allowlist
  ($enc->allowedKeyAlgorithms[] = XMLSecurityKey::RSA_1_5); enableLegacyMode()
  does both. Set allowedKeyAlgorithms (or the static argument) to null to
  apply no key-transport allowlist.
- Requires PHP 8.3 or later
- Requires phpseclib 3.0.58 or later (4.0.2 required 3.0.57 or later).
- Parsing an RSA-OAEP EncryptionMethod now rejects unknown or
  wrongly-namespaced child elements, duplicate parameters, and
  malformed content. 4.0.x ignored these children. An xenc:KeySize
  of 1 to 999999, including a leading plus and leading zeros, is accepted.
  When present, it must match the RSA key size in bits. Omission is unchanged.
- Signature verification now defaults to SHA-2 algorithms.
  XMLSecurityDSig::$allowedSignatureAlgorithms and $allowedDigestAlgorithms
  default to DEFAULT_SIGNATURE_ALGORITHMS (RSA-SHA256/384/512, RSA-PSS
  SHA256, ECDSA-SHA256/384/512) and DEFAULT_DIGEST_ALGORITHMS
  (SHA-256/384/512) instead of null, and apply to verify() and
  validateReference() as well as verifyDocument(). Signing is unaffected.
  SHA-1 (rsa-sha1, hmac-sha1, sha1 digests) requires
  enableLegacyMode(), which adds them to the lists, or adding them to the
  lists explicitly; RIPEMD-160 digests require a list entry. DSA signatures
  are not supported. verify() and
  validateReference() treat a null list as no restriction.
  verifyDocument() falls back to the corresponding DEFAULT_* list when a
  list is null, for that call only, and restores the property afterwards.
- Data decryption now defaults to AES-GCM.
  XMLSecEnc::$allowedDataAlgorithms defaults to DEFAULT_DATA_ALGORITHMS
  (AES-128/192/256-GCM) instead of null. This allowlist applies to an
  EncryptedData whose EncryptionMethod is AES or 3DES. An EncryptedData
  encrypted directly with an RSA key-transport algorithm is governed by
  allowedKeyAlgorithms and allowRSA15KeyTransport, not allowedDataAlgorithms.
  The $allowedDataAlgorithms argument of staticLocateKeyInfo() and
  XMLSecurityKey::fromEncryptedKeyElement() defaults to the same list; it is
  copied onto the inner context and does not affect decryption. AES-CBC and
  TripleDES-CBC
  require enableLegacyMode(), which adds LEGACY_DATA_ALGORITHMS, or an
  explicit allowedDataAlgorithms list. Set the property or the static
  argument to null to apply no data-encryption allowlist. A null list is
  left null by enableLegacyMode(). Encryption still uses the algorithm of
  the caller-supplied key.

Compatibility:
- omit_uri on a nested element now throws an Exception before a Reference
  is added. omit_uri on the document element digests the whole document,
  including any processing instruction before the root, as omit_uri on a
  DOMDocument does. Reference a nested element by ID instead. An omitted
  URI and URI="" (force_uri) remain separate options.

Security Improvements:
- Harden add509Cert() URL fetching against SSRF: only http/https by default
  (file:// requires options['allow_file_scheme']); resolve the host and reject
  loopback/private/link-local/reserved/CGNAT addresses; disable HTTP redirects
- Reject IPv4-mapped / IPv4-compatible IPv6 certificate URL hosts (e.g.
  ::ffff:127.0.0.1, ::ffff:169.254.169.254): unwrap the embedded IPv4 and apply
  the same private/reserved/CGNAT checks (PHP's FILTER_FLAG_NO_* treats mapped
  addresses as public)
- Fail closed on unknown Reference Transform algorithms; recognize
  enveloped-signature explicitly. validateReference() no longer always detaches
  the Signature from the caller DOM (that broke C14N of ds:Object targets and
  left half-mutated trees on failure); enveloped-signature removes Signature
  only when it is a proper descendant of the node being digested
- Tighten same-document Reference URIs to empty URI and "#id" only (reject
  "?query", bare "#", and external URIs); share parsing between processRefNode()
  and getRefNodeID(). Same-document refs always omit comments
- Reject hostile idKeys attribute names (no whitespace / XPath operators) via
  Utils\XPath::filterAttrName; invalid names throw
- Reject duplicate CanonicalizationMethod / SignatureMethod under SignedInfo and
  duplicate DigestMethod / DigestValue / SignatureValue during verify
- Reset the cached DOMXPath in locateSignature() so instance reuse across
  documents cannot fatal with "Node from wrong document"
- verifyDocument() no longer permanently overwrites instance algorithm
  allowlists (restored in finally)
- addReference() / addReferenceList() / sign() / add509Cert() throw instead of
  silently no-oping when SignedInfo / signature context is missing; sign()
  requires setCanonicalMethod() and a SignatureMethod element
- Require correct namespace URIs for InclusiveNamespaces (exc-c14n) and XPath
  transform children (not localName alone)
- Reject a DOCTYPE in decrypted XML (defense against entity-expansion / XXE in
  attacker-crafted encrypted content)
- Reject a DOCTYPE in documents being signature-verified (locateSignature). Closes
  the entity-reference signature bypass where an Id="&e;" attribute is resolved by
  getAttribute() but invisible to the XPath reference lookup (libxml2
  xmlXPathNodeValHash bug, the CVE-2025-23369 root cause), letting verify()
  validate a different node than the application reads. Opt out with
  XMLSecurityDSig::$forbidDoctype = false
- Deny RSA-1.5 (PKCS#1 v1.5) key transport on decryption by default
  (Bleichenbacher / XML-Encryption backward-compatibility attack); opt in via
  XMLSecEnc::$allowRSA15KeyTransport. Add optional key-transport / data
  algorithm allowlists ($allowedKeyAlgorithms / $allowedDataAlgorithms, with
  DEFAULT_KEY_ALGORITHMS / DEFAULT_DATA_ALGORITHMS presets)
- Use a single generic "Failure decrypting Data" error for all decryption
  failures (bad padding, cipher error, failed RSA unwrap) so callers cannot
  build a CBC padding oracle from distinguishable errors. Catch and normalize
  phpseclib throws (LengthException, BadDecryptionException, RuntimeException,
  etc.) on symmetric and RSA decrypt paths so exception type/message cannot
  form a ciphertext-validity oracle either.
- Add verifyDocument(): safe-by-default signature verification that requires a
  caller-pinned key (never trusts KeyInfo), enforces a SignatureMethod/DigestMethod
  algorithm allowlist, fails closed on unvalidated references, and returns the
  validated node set. New $allowedSignatureAlgorithms / $allowedDigestAlgorithms
  properties (default strong: SHA-256+ digests, RSA-SHA-256+/PSS signatures);
  the low-level verify()/validateReference() primitives remain unrestricted for
  backward compatibility unless these properties are set (except the
  SignatureMethod/key-algorithm binding, which is always enforced -- see below).
- Reject asymmetric key material (X.509 certificate / PEM public key) being
  loaded as an HMAC key; prevents signature key/algorithm confusion forgery
- verify() now always binds the document's SignatureMethod to the algorithm of
  the supplied key (previously only when $allowedSignatureAlgorithms was set),
  so a mismatch is rejected even on the low-level path. Blocks algorithm
  substitution / key confusion (e.g. downgrading an RSA signature to hmac-sha1
  so a public key is used as the HMAC secret)
- Bound EncryptedKey / RetrievalMethod resolution depth (prevents recursive
  key-reference DoS / memory exhaustion)
- Reject XPath (REC-xpath-19991116) Transforms during verification by default.
  The transform evaluates a document-supplied XPath expression in 
  validateReference()  before any crypto runs, so a crafted expression is a 
  pre-auth CPU denial-of-service; the expression is arbitrary XPath by design 
  and cannot be sanitized. SAML / WS-Security do not use XPath transforms. Opt in
  with XMLSecurityDSig::$allowXPathTransforms = true. Signing is unaffected
- Cap XPath transforms (max 5) and namespaces per XPath transform (max 20);
  overridable via $maxXPathTransforms / $maxXPathNamespaces
- Fail closed on unresolved, external, and duplicate-Id Reference URIs
- Reject unknown CanonicalizationMethod algorithms
- Use hash_equals for digest and HMAC compares; HMAC verify returns 1/0
- Validate ISO 10126 pad length on CBC decrypt
- Harden decrypted XML parsing (LIBXML_NONET); restrict certificate URL fetches
- Use random_bytes for GUID generation
